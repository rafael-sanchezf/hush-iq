## What is hackathon work (built Oct 26 to Nov 4)

Everything after the import commit. The commit history of this repository is the record; the pieces, in
the order they land:

1. **Hosted API.** The FastAPI service deployed as a public endpoint (first on Vercel, Oct 26 night), open
   CORS, cache in `/tmp`, a prefix shim. Commit "Hosted API". Since Nov 2 one host serves every piece
   (`api/index.py`): the score API beside `/read`, `/verdict` and `/adjust/permits`, CORS open for POST.
2. **Score engine v2** (`packages/model/noise_score/v2.py`, `/v2/score`). Each noise source is ranked against
   a fixed Manhattan sample, the ranks are averaged with weights set by the renter's answers (sleep hours,
   daytime noise, what bothers them), and any source in Manhattan's loudest 5% caps the verdict. Decibel-shaped
   estimates stay inside each source; the response carries ranks and verdicts only. v1 stays live. Rules in
   `packages/model/ENGINE_V2.md`.
3. **Listing reader agent** (`services/agent/`). A listing URL, pasted text or photos go to a Meta model
   (Muse Spark through the Meta Model API, multimodal); it extracts the address, floor and exposure, quotes
   the span of the listing each came from, asks only for what it could not read, then geocodes and scores.
   A `submit_listing` tool refuses a result whose fields have no quoted span. Each turn is shown.
4. **Bounded AI adjustments: the permit reader** (`services/adjust/`, `POST /adjust/permits`). Muse Spark
   reads the job description of each DOB permit on the building's tax block (a facade job runs months, a new
   building years, an interior renovation is muffled) and emits one construction adjustment, capped at two
   steps, citing the permits it used; a `submit_adjustment` tool refuses an adjustment whose cited permits are
   not in the pull or whose size exceeds the cap, and the cap comes from config, never from the model. Live on
   the host; three recorded live runs are in `services/adjust/tests/fixtures/live/`, and the site's method page
   shows their before and after. It is not yet wired into the score the site and the extension show. Reading 311 complaint text and venue hours was cut for Nov 4.
5. **Grounded verdict writer** (`services/verdict/`, `POST /verdict`). The "what you'll hear" paragraph for
   this renter, generated by Muse Spark 1.3 through the Meta Model API in JSON-schema mode, its citations an
   enum of the evidence lines sent, validated server-side, template fallback. A Muse Spark Open path (Baseten,
   `meta-models/muse-spark-open-1026`) is in the code and runs once a host key is set; no open-weight model
   serves this submission today.
6. **Chrome extension** (`apps/extension/`). On a StreetEasy or Zillow listing it reads the page, sends the
   text and photos to the listing reader, and shows the verdict card in Chrome's side panel, with every source's
   evidence in its hover. A labelled replay runs when the host is unreachable.
7. **Website** (`apps/web/`): live demo, API docs, the page for listing sites, the method page. A live service
   that fails or runs long is replaced by its labelled stand-in, never by a silent one.
8. **An eval** of 20 cases that checks every citation points at a real row, run on every change.

Compare (two or three listings side by side) and voice intake were cut for Nov 4. The demo video shows only
pieces 1 to 8. The model's prior existence is said out loud in its first ten
seconds.
